# v4 pilot — preregistration

Committed before any evaluation call. Evaluation uses seeds 1–5 only; everything below was fixed on development
seeds 100–109. **The code is frozen with this file:** `run` refuses evaluation seeds unless this file and every file
under `antelligence/` and `scripts/` are committed and unmodified (`check_committed`, `GATED_TREES`). Evaluation runs
from the commit that adds this file; any later code change is reported in FINDINGS.md as a deviation. This is a **pilot**: 15 runs per arm per world can detect only large effects. All results are
reported as pilot estimates.

## 1. Question

On task variants where a hidden assumption breaks (so a hand-written script fails), does a swarm of decision-model
workers led by a queen recover as much of the gap to the adapted script as a swarm where a strong model controls
every agent — and with fewer seconds per decision?

## 2. Worlds

Both worlds are deterministic, seeded and replayable (kernel Scheduler, hash-chained event log).

| World | Port of | Agents | Length | Score |
|---|---|---|---|---|
| `foraging_sb` | SwarmBench foraging (MIT) | 10 | 100 ticks | food deliveries to the nest |
| `graph_coloring` | AgentsNet colouring (MIT) | 8 | 4 rounds (1 per tick) | share of properly coloured edges |

Departures from the originals are listed in each package README (`antelligence/worlds/*/README.md`).
Peer messages are generated by the world and written into each agent's state; agents choose actions only.

**Judgement checks (yes/no, at most two per agent per tick).** Foraging: "Is the food patch you remember still
there?" and "Is the nest where you remembered it?" (asked when the agent remembers that spot). Colouring: "Did every
neighbour send you a message this round?" and "Are all your neighbours' reports honest, with changes only where a
clash forced them?" (the second only when a neighbour's report changed). **Worker groups** (fixed): foraging agents 0–4 and 5–9; colouring agents 0–3 and 4–7.

**Sensing.** Every arm — scripts and models — gets the same state, written in words, plus the same action list and
the same fixed task instructions (`PilotWorld.instructions`, identical in every condition). The state describes and
never suggests a move. Scripts read the same facts in structured form; S and S′ in foraging keep a map memory built
from their own views (a script's memory, not hidden state). Model arms are stateless per tick; in the framework arms
the board is the swarm's memory.

## 3. Variants and the validity check

| World | Variant | What breaks | S′ |
|---|---|---|---|
| foraging | V1 food runs out | the patch empties after 6 pickups; a new patch appears elsewhere | explores when the patch is empty |
| foraging | V2 sensor flips | from tick 30 one axis of every agent's view is mirrored | knows the flip and un-mirrors |
| colouring | V1 lost messages | each message dropped with probability 0.3 | resends until acknowledged |
| colouring | V2 one liar | agent "1" reports random colours; only honest agents' edges are scored | knows the liar and ignores it |

Both variants per world passed the validity check on development seeds 100–109 (S′ ≥ 0.9 × S on base; S ≤ 0.5 × S′
on the variant). Files: `validity-foraging_sb.json`, `validity-graph_coloring.json`. The colouring V2 margin is thin
(S/S′ = 0.44 against the 0.5 limit). Colouring S is name-priority greedy, which is weak on base (0.735) — a
reactive S was not broken by either variant.

## 4. Seeds

Evaluation seeds 1, 2, 3, 4, 5 × conditions base, V1, V2 = 15 runs per arm per world. DS-all on foraging runs seeds
1–3 only (9 runs), for budget. Development seeds 100–109 were used for everything before this file and are never
used in evaluation.

## 5. Arms

| Arm | Who decides | Queen | Escalation | Model calls |
|---|---|---|---|---|
| S | script | — | — | 0 |
| S′ | adapted script (variants only) | — | — | 0 |
| DS-all | DeepSeek V4.1 Flash (`deepseek/deepseek-v4.1-flash`, Nous, non-thinking), every agent every tick | — | — | high |
| Q-all-0.8B / 4B / 9B / Qwen3.8-27B | Qwen on vLLM (one L40S), every agent every tick, non-thinking | — | — | high |
| F-Laya | Laya typed decisions (local `laya-serve`) | DeepSeek | Qwen3.5-9B | low |
| F-Jev | Jev `jev-1.13.0` | DeepSeek | Qwen3.5-9B | low |
| F-Jev-noQueen | as F-Jev, every action allowed | — | Qwen3.5-9B | low |
| F-Jev-noEsc | as F-Jev, no escalation | DeepSeek | — | low |

**Cut applied before evaluation (goal §8 RunPod cut 1): Q-all Qwen3.5-27B is dropped** (see §9). The evaluation
plan is `plan.json` (314 cells, 27B absent); the arms table in code still lists it but it is not run.

Every-agent arms return one JSON `{"action": id}` with ≤ 64 output tokens, options shuffled by a seeded RNG.
Framework workers each tick answer one `choice` "Which action?" over the queen's allowed actions plus
`report: my local evidence disagrees`, and up to two yes/no checks; the question text carries the task instructions
and the queen's goal. A `report` answer, or a check with P(yes) < 0.5, posts a report on the board. The queen
(DeepSeek, ≤ 300 output tokens, non-thinking) sees only worker reports, aggregate counts and her own past signals,
and speaks every 10 ticks in foraging and every round in colouring, setting a goal (≤ 120 characters) and the allowed
actions for each of two fixed worker groups. Failed or invalid queen replies keep her previous orders.

## 6. Escalation thresholds (fixed from Phase 0)

Phase 0 asked 300 labelled questions from development seeds (150 per world; half judgement, half move) of Laya, Jev,
DeepSeek and Qwen3.5-9B. Aggregates: `phase0/phase0-summary.json` / `.md`. Move questions are scored against the set
of equally good actions (P = probability mass on that set).

- **Judgement (yes/no) questions escalate to Qwen3.5-9B when 0.2 < P(yes) < 0.8** (goal default; 0.3/0.7 was within
  one item of it on development data).
- **Move choices never escalate** (`c_min = 0`). On development data escalating Jev's moves lowered accuracy at every
  threshold tried (0.700 → 0.667 at the goal default 0.5), and Jev beat Qwen on the escalated moves.
- The same rule applies to F-Laya and F-Jev. Laya was below chance in Phase 0 (judgement 0.413 vs 0.700 majority
  rate; move 0.253 vs 0.381); it is kept because the primary comparison includes F-Laya, and reported as is.
- If an escalation call fails, the decision model's own answer is used and the failure is logged.
- Consequence to state now: Laya's yes/no probabilities on development data spanned only 0.29–0.80, so at this band
  **F-Laya escalates essentially every judgement** — its checks are effectively Qwen3.5-9B's (Phase 0: Laya-all-
  escalated judgement accuracy 0.820 = Qwen's). F-Laya's moves are Laya's own. F-Jev escalated 34.7% of judgements
  on development data.
- Choice confidence in the Phase 0 grid used the maximum probability as a proxy (rows lacked backend confidence).

## 7. Metrics (per run)

Score; G for variant runs; seconds per decision (median and p90 of wall-clock per physical model call, network
included, cache hits excluded, **pooled over all of the arm's physical calls — worker, queen and escalation — in
base and variant runs of both worlds**; per-role medians are also reported. Laya runs locally on the Mac, Jev and
DeepSeek over the network, Qwen on a RunPod L40S: the comparison is of the deployed systems, not like-for-like
hardware); ticks and wall-clock per episode; calls, tokens, dollars; compliance (share of worker
answers inside the queen's allowed set); report precision (share of `report` answers the simulator confirms — true
when none of the simulator's equally good actions was allowed); escalation rate. Hardware/region per arm is recorded.

**G.** G = (score − S) / (S′ − S), using the S and S′ scores for the same world, seed and condition. G is
**undefined** (excluded, and counted per arm as `g_undefined`) when S′ − S < 2 deliveries (foraging) or < 0.05
(colouring). G is not clipped. *Deviation from the goal, fixed before evaluation:* the goal defines G without a
floor; a near-zero S′ − S makes G explode. The floors are about a fifth of the smallest development-mean gap
(foraging ≈ 10–12 deliveries, colouring ≈ 0.49–0.76). Runs where a cell errored (provider failure after 3 retries)
have no G and are counted as errors.

## 8. Analysis (fixed now)

- **Primary comparison:** F-Jev vs DS-all, and F-Laya vs DS-all, on mean G over variant runs, **paired by
  (world, seed, condition)** — only keys where DS-all, F-Jev and F-Laya all have a defined G enter, the same set for
  both comparisons and for go/no-go (at most 16: foraging seeds 1–3 and colouring seeds 1–5, V1 and V2).
  *Deviation from the goal, acknowledged:* the goal says "paired by seed"; restricting to the shared keys is what
  pairing means when DS-all foraging has only 3 seeds. Percentile bootstrap 95% interval of the mean difference,
  resampling seed clusters (a cluster = all keys with that seed number, across both worlds), 10,000 resamples, RNG
  seed 20261011.
- **Go / no-go for a full study:**
  - **Go:** a framework arm's paired mean G ≥ DS-all's paired mean G − 0.10 **and** its median seconds per decision
    (all its physical model calls, both worlds) is lower than DS-all's.
  - **No-go:** both framework arms have paired mean G < 0.10.
  - If both hold, **No-go** takes precedence (`go_also_holds` is reported).
  - **Otherwise:** unclear.
- **Also reported (descriptive, no decision rule):** every arm's base-task score as a share of S; per-world and
  per-condition results; mean G for each Q-all model and the ablations; time to finish (ticks and wall-clock per
  episode) and cost per arm; per-role seconds per decision; chance baselines next to every Phase 0 accuracy;
  counts of errored cells and undefined G per arm.
- **Incomplete arms:** if a hard stop ends evaluation early, every analysis uses the cells that completed; an arm
  missing more than 20% of its planned cells is reported as incomplete, and the go/no-go verdict is reported as
  "unclear" if any of DS-all, F-Jev or F-Laya is incomplete.
- Errors: provider errors are retried up to 3 times, then marked as errors (the agent does nothing that tick).
  A run is never rerun to change its result; completed cells are never rerun.

**Known before evaluation (development plumbing, seed 100, base; `dev/plumbing-summary.json`).** In colouring every
model arm beat S (S 0.50; DS-all 0.58; Q-all-9B 0.75; F-Jev 0.75; F-Laya 0.92; F-Jev-noQueen 0.75), with code
between plumbing runs 1 and 3. In foraging no model arm delivered any food in any plumbing run after the route hint
was removed (S 15). With the final state text (own 5×5 view in words plus last move; plumbing run 4) DS-all and
F-Jev-noEsc both delivered 0. We expect foraging G to be at or below 0 for every model arm; this is recorded here so
it cannot be explained away afterwards.

evaluation (development): see `~/Desktop/antelligence-v4-status.md`; RunPod $0.191 (one 10.5-minute pod).

- Nous ≈ $1.2 for evaluation (DS-all foraging ≈ $0.09 per run × 9; colouring ≈ $0.002 per run; queen ≈ $0.004
  per foraging run) → no cut. Nous cut 2 ("queen every 20 ticks") would apply to foraging only (colouring has 4

- RunPod at $1.09/hr: Qwen3.5-9B session (Q-all-9B plus the three framework arms that escalate) ≈ $0.65–0.95;
  0.8B and 4B ≈ $0.25 each; each 27B FP8 ≈ $0.69 → ≈ $2.5–2.8 with $2.56 left. **Cut 1 applied: drop Q-all
  Qwen3.5-27B.** If the running total would still cross the hard stop, cut 2 (drop Q-all Qwen3.5-4B) applies.
- Pod order: Qwen3.5-9B (framework arms + Q-all-9B), Qwen3.5-0.8B, Qwen3.8-27B (FP8), Qwen3.5-4B. One model at a
  time; each pod is terminated as soon as its runs finish. Revisions pinned (`scripts/v4_pod.py`).

**Stop and report if:** any key would be printed or committed; private data would be committed; the suite is red for
more than 60 minutes; any budget reaches its hard stop; 3 days have passed.
